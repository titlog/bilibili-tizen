# BiliSpike 实操手册（VS Code 版）

开发者模式已经打开，剩下的都是电脑上的事。整套流程大约 40 分钟。

不用装 Tizen Studio。VS Code 的 `tizentv` 扩展自带打包、签名、部署、热重载，是 Samsung 官方维护的 `vscode-extension-tizentv`。

---

## 开工前的确认

进电视 **Apps** 界面，左上角应该标着 **"Develop Mode"**。看到这个标记才算真的生效，看不到就是没生效，别往下走。

同时确认电视和电脑在同一网段：

```bash
ipconfig getifaddr en0        # 电脑 IP
```

电视 IP 在 **设置 → 一般 → 网络 → 网络设置 → IP 设置**。前三段要一样。

---

## 第 1 步 — 装扩展

VS Code 扩展面板搜 **tizentv**，认准 publisher 是 **tizensdk**（列表里显示 14K 安装、5 星那个）。

你已经装的那个 "Tizen Extension" 是 .NET/C# 那条线的，我们做 web 应用用不上，留着不影响。

装完打开 **Settings**（`Cmd+,`），搜 `tizentv`，填两项：

| 配置项 | 填什么 |
|---|---|
| `tizentv.hostPCAddress` | 你电脑的 IP |
| `tizentv.targetDeviceAddress` | 电视的 IP |

`hostPCAddress` 必须和你在电视开发者模式对话框里填的那个 IP 一致，否则电视会拒绝连接——它只接受来自那一个地址的请求。

---

## 第 2 步 — 拿 DUID

证书要绑定电视的 DUID，先拿到它。三条路，从省事到麻烦：

**① 电视菜单**（不需要任何工具）

**Menu → Support → Contact Samsung → Unique Device ID**

部分机型菜单里没有 "Contact Samsung"，那就走下面两条。

**② 命令行**

如果你手上有 sdb（装过任何 Tizen 工具链都会带）：

```bash
sdb connect 192.168.1.50:26101
sdb shell 0 getduidgadget
```

**③ 让它自动填**

在第 3 步创建分发证书时，如果电视已经连上，DUID 通常会自动预填进去。先试这条，省事。

DUID 是一串长字符串，复制下来备用。

---

## 第 3 步 — 生成证书

`Cmd+Shift+P` → **Tizen TV: Run Certificate Manager**

创建一个 profile，两部分：

**Author Certificate（作者证书）**
需要登录 Samsung 账号。设一个密码，**记住它**，后面打包要用。

**Distributor Certificate（分发证书）**
把第 2 步的 DUID 填进 DUID 列表。

> **这一步最容易出错的地方**：必须是 **Samsung** 证书，不是 Tizen 证书。三星电视只认三星分发证书，用 tizen.org 的证书签出来的包装不上，报的还是一个很含糊的错。

分发证书**有效期一年**。一年后要回来重新生成、重新打包。日历上记一笔。

---

## 第 4 步 — 拿一个 playurl

随便找一个**公开的、不需要大会员**的视频，从网页地址取 `bvid`（`BV` 开头那串）。

**先拿 cid：**

```bash
curl -s -H "Referer: https://www.bilibili.com" \
     -H "User-Agent: Mozilla/5.0" \
     "https://api.bilibili.com/x/player/pagelist?bvid=BV1xx411c7XD" \
     | python3 -m json.tool
```

取 `data[0].cid`。

**再拿播放地址：**

```bash
curl -s -H "Referer: https://www.bilibili.com" \
     -H "User-Agent: Mozilla/5.0" \
     "https://api.bilibili.com/x/player/playurl?bvid=BV1xx411c7XD&cid=你的CID&qn=32&fnval=1" \
     | python3 -m json.tool
```

取 `data.durl[0].url`。

这两个 API 调用**自己也要带 Referer 和 User-Agent**，不带返回 -403。

**参数为什么这么选：**

- `fnval=1` 返回单个 MP4，不是 DASH。DASH 音视频分离，spike 阶段不需要这层变量
- `qn=32` 是 480P，不需要登录。**第一次一定用这个**——加 SESSDATA 拿高清会同时引入"登录"和"清晰度"两个变量，而这次实验的全部目的就是隔离出 Referer 这一个

**链接一两个小时就过期。** 测的过程中突然全变红，先换新链接再怀疑代码。

---

## 第 5 步 — 填进配置

VS Code 打开 `BiliSpike/js/config.js`：

```js
var VIDEO_URL = "https://cn-...bilivideo.com/upgcxcode/...";
```

其他三个变量第一次跑都不动。

---

## 第 6 步 — 打包安装

在 VS Code 里打开 `BiliSpike` 文件夹作为工作区，然后：

`Cmd+Shift+P` → **Tizen TV: Build Signed Package**

会问你第 3 步设的证书密码。产物 `BiliSpike.wgt` 直接扔在工作区根目录。

`Cmd+Shift+P` → **Tizen TV: Launch Application**

推到电视上并启动。

---

## 第 7 步 — 在电视上跑

应用在 **Home → Apps**，往右翻到最后，图标是个粉色方波。

全部用方向盘操作：

| 键 | 动作 |
|---|---|
| ↑ / ↓ | 在「Run all three」和三项测试间移动，选中行有粉色高亮 |
| 中间确认键 | 运行选中项 |
| 返回键 | 播放中中断 / 报告页退出 |

默认选中最上面的 **Run all three**，进去直接按确认键跑全套。

测试 02 会全屏播 12 秒然后自己回到报告页。

---

## 第 8 步 — 读结果

屏幕最上方那行大字就是结论：

| 01 | 02 | 03 | 含义 |
|---|---|---|---|
| ✅ | ✅ | ❌ | **最好的结果。** AVPlay 不发 Referer 而 CDN 接受，WebKit 发了被拒。项目通畅 |
| ✅ | ✅ | ✅ | 更好，这个链接 CDN 根本没查 Referer |
| ✅ | ❌ | ❌ | 链接能通但 AVPlay 解不了。问题在编码或容器，换个 `qn` 再试 |
| ❌ | ❌ | ❌ | CDN 要 Referer，需要局域网代理，成本要重算 |

拍照发我，我们定下一步。

## Wits：跑通之后立刻启用

`Cmd+Shift+P` → **Tizen TV: Wits Start**

实时热重载。改完代码电视上立刻生效，**不用重新打包、不用重新签名、不用重新安装**。支持 2017 年以后的机型。

之后改一次 `config.js` 试一个新链接，从三十秒变成零秒。真正开始移植界面的时候，这个差别是几十倍的。

`Tizen TV: Wits Watch` 是只监听不重装，`Tizen TV: Wits Stop` 停。

## 报错对照表

| 现象 | 原因 |
|---|---|
| Launch 时连不上电视 | `tizentv.hostPCAddress` 和电视上填的 IP 不一致；电视只接受那一个地址 |
| 装包报签名无效 | 证书选成 Tizen 了，必须是 Samsung |
| 装包报 DUID 相关错误 | 分发证书里没填 DUID，或填的不是这台电视的 |
| 测试 01 显示 `status 0` | `config.xml` 里的 `<access origin="*">` 没生效，检查文件有没有被覆盖 |
| 测试 02 报 `CONNECTION_FAILED` | 这是 403 在 AVPlay 里的样子，或者链接过期了 |
| 应用装上打不开 | 多半是 JS 报错，用 **Tizen TV: Debug Application** 挂 Chrome Web Inspector 看 |
| 过一年突然全失效 | 分发证书到期，回第 3 步重新生成 |

## `tizentv` 扩展不好使的话

这个扩展维护得不算勤，万一证书管理器报错，退路按顺序：

1. **官方新扩展**：装 **Tizen Extension**（publisher `tizen`）+ **Tizen TV Extension**（publisher `samsungtvsdk`），在 Tizen Extension 的 Activity Bar → Packages → Advanced 里装 TV extension
2. **Tizen Studio 的 CLI-only 包**：不要 IDE 那个几个 G 的安装包，只装命令行工具
3. **Docker**：jellyfin-tizen 社区有现成镜像，一条命令完成构建和签名，完全不碰本地工具链

第 3 条最适合你，需要的话我把它改造成跑 BiliSpike。

---

## 跑通之后的路线

**Spike 1.5**：`qn` 改 64 或 80，`COOKIE` 填 `SESSDATA=你的值`，验证 AVPlay 能不能正确带 cookie 拿高清。

**Spike 1.6**：`fnval` 改 16 试 DASH，验证音视频分离流能不能播。正经客户端都走 DASH。

**Spike 2**：扫码登录 + WBI 签名，然后开始把 `asdf17128/bili-webos` 的界面搬过来。这部分没有平台层面的未知数，照着 API 文档写，适合交给 Claude Code 批量做。
